### 数据库验证

隔离分支 `m8-reliability`（schema-only）先验证，再向主项目应用两个新增迁移；没有修改旧迁移、历史版本或现有 RLS。

`node scripts/check-atomic-runs.mjs <branch-project-config>` 通过：

1. 在版本插入后故意让消息约束失败，版本、指针和用量全部回滚。
2. 同一请求重复提交返回同一版本，消息/用量不重复。
3. 两个请求基于同一版本并发保存，只有一个成功，另一个收到冲突。
4. 伪造所有者和浏览器直接调用提交 RPC 均被拒绝。

发现 InsForge 对 SQL serialization 异常返回网关超时；第二迁移将预期冲突改为结构化结果，由 HTTP 路由映射为 409。原子写入异常仍触发 PostgreSQL 回滚。

## M9 — 版本检查与发布核对

- 纯静态检查：入口、受支持的路径、6 文件/100 KB 限制、HTML/CSS 字面资源引用；外部依赖列出且不请求，不检查动态 JS 行为或模块导入。
- 所有者快照接口返回版本 ID、按排序文件内容计算的 SHA-256、检查时间、种类及结果。记录按请求生成；浏览器观察只保留当前会话，不宣称已保存长期测试报告。
- 预览消息绑定 source window、sessionId 和 versionId，并验证结构与长度。启动等待 10 秒，DOMContentLoaded 后观察 3 秒；之后收到错误仍改为报错状态。资源加载错误也被捕获。
- 发布服务端重新检查确切版本，静态错误返回 422；读取时或提交时当前指针变化返回 409。前端无当前会话观察时要求先预览，有运行错误时要求 Resolve；客户端诊断不作为权限证明。
- 76 项单测通过；类型、lint、生产构建通过。发布 API 回归通过（slug、冲突、更新、匿名访问、下线、未登录拒绝）。
